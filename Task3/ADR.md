### <a name="_qmphm5d6rvi3"></a>**Решение**

Предлагается гибридная архитектура, которая минимизирует изменения в существующих системах и подготавливает переход к
микросервисам.

Основные архитектурные решения:

1. Новый сервис "Депозитный сервис" - микросервис на Java Spring Boot для обработки заявок на депозиты, совместимый
   с экспертизой команды кол-центра
2. Сервис управления ставками - для централизованного управления ставками депозитов вместо Excel-файлов
3. Асинхронная интеграция через очереди сообщений для снижения нагрузки на АБС

Диаграммы:

- `context_diagram.puml` - диаграмма контекста системы
- `container_diagram.puml` - детализированная архитектура контейнеров

Технологический стек:

- Депозитный сервис: Java Spring Boot + PostgreSQL (совместимость с командой кол-центра)
- Сервис ставок: .NET Core + MS SQL (совместимость с интернет-банком)
- Очереди: Apache Kafka (по требованию бизнеса)

Логика решений:

- Снижение нагрузки на АБС через асинхронную обработку заявок
- Использование знакомых технологий для упрощения поддержки
- Подготовка к полной автоматизации процесса в будущем

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

1. **Прямая интеграция с АБС** - быстрее в реализации, но создает риск перегрузки критической системы
2. **Полная модернизация интернет-банка** - требует значительных затрат и зависимости от подрядчика

**Недостатки, ограничения, риски**

- Увеличение сложности системного ландшафта
- Необходимость синхронизации данных между системами
- Дополнительные точки отказа
- АБС остается узким местом при вертикальном масштабировании
- Зависимость от стабильности Kafka для критических операций
- Необходимость ручной обработки заявок в MVP
- Потенциальная необходимость доработки подрядчиком при возникновении проблем совместимости
